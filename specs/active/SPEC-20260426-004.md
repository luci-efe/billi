## Purpose

Establish the AI infrastructure using Mastra to provide a framework for the "Billi" assistant, enabling deterministic financial tools and a generative conversational interface with Mexican context.

## Scope

### In Scope
- Installation of Mastra within the `apps/api` workspace.
- Configuration of the `BilliAgent` with its persona and system prompt.
- Implementation of a base tool `getTransactions` to allow the agent to query the user's history from Turso.
- Integration of the Mastra agent into the Hono API.

### Out of Scope
- RAG ingestion and corpus vectorization (on hold for data).
- Voice or image capture processing.
- Vector database setup (to be handled in a separate RAG-specific spec).

## Requirements

### REQ-001: Mastra Core Integration
**Priority:** P0
**Description:** The system SHALL have Mastra installed and configured within the `apps/api` workspace.

#### Acceptance Criteria
- **GIVEN** a request to the API **WHEN** the Mastra instance is called **THEN** it responds without errors.

#### Scenarios
- **Happy path:** Mastra initializes and an agent is accessible via a route.
- **Error case:** Missing environment variables (API Keys) result in a clean error response.

### REQ-002: Billi Agent Persona
**Priority:** P0
**Description:** The system SHALL define a `BilliAgent` with a system prompt optimized for Mexican financial regulations (SAT, RESICO) and professional context.

#### Acceptance Criteria
- **GIVEN** a generic query **WHEN** the agent responds **THEN** it maintains the persona of a helpful Mexican financial assistant.

#### Scenarios
- **Happy path:** Agent explains a Mexican tax concept or identifies itself as Billi.

### REQ-003: Core Financial Tool - getTransactions
**Priority:** P0
**Description:** The system SHALL provide a tool `getTransactions` that the agent can use to query the user's transaction history from Turso.

#### Acceptance Criteria
- **GIVEN** a user with existing transactions **WHEN** they ask "What was my last expense?" **THEN** the agent calls the `getTransactions` tool and provides the correct answer.

#### Scenarios
- **Happy path:** Agent successfully retrieves and narrates a transaction.
- **Empty case:** Agent correctly reports that no transactions were found.

## Technical Approach

- **Mastra Instance:** Centralized Mastra instance in `apps/api/src/mastra/index.ts` to register the `BilliAgent`.
- **Agent Configuration:** Use `@mastra/core/agent` to define `BilliAgent` with Mexican-specific system prompts.
- **Tooling:** Implement `getTransactions` using `createTool` from `@mastra/core/tools`, querying the Turso/Drizzle database via `transactionRepo`.
- **Hono Integration:** Expose the agent via `/api/ai/chat` (non-streaming) and `/api/ai/health`.

## Test Strategy

The test suite is implemented in `apps/api/src/tests/mastra.test.ts` using Vitest and Cloudflare Workers testing tools (`cloudflare:test`).

1.  **Integration Testing:** Verify the Hono API correctly mounts and exposes Mastra endpoints (`/api/ai/health`, `/api/ai/chat`).
2.  **Persona Validation:** Use natural language queries to assert that the LLM response contains required keywords (Billi, México, SAT/RESICO) indicating the persona is active.
3.  **Tool Verification:** Request transaction data to force the agent to call the `getTransactions` tool, verifying end-to-end integration between the agent, the tool, and the Turso database.
4.  **Error Handling:** Simulate missing configurations and empty data states to ensure graceful failures.
