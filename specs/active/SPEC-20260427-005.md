# SPEC-20260427-005: Premium Subscription & Dodo Payments

**ID:** SPEC-20260427-005
**Name:** premium-subscription-dodo
**Stage:** SPEC
**Created:** 2026-04-27
**Updated:** 2026-04-27
**Author:** Gemini CLI

## Purpose

Implement the premium monetization layer using Dodo Payments, enabling users to upgrade their accounts to access advanced AI and storage capabilities while managing their subscription lifecycle.

## Scope

### In Scope
- Integration with Dodo Payments SDK/API.
- Premium landing page and plan selection UI.
- Checkout flow and success/failure handling.
- Entitlement management (Free vs Premium flags).
- Webhook handling for subscription events (renewal, cancellation).

### Out of Scope
- Support for other payment providers (Stripe/PayPal).
- Enterprise/Team billing.
- Referral/Coupon system (deferred).

## Requirements

### REQ-001: Dodo Payments Checkout Integration
**Priority:** P0
**Description:** The system SHALL integrate with Dodo Payments to facilitate secure checkout for premium plans.

#### Acceptance Criteria
- **GIVEN** a user on the pricing page **WHEN** they click "Upgrade" **THEN** they MUST be redirected to a Dodo Payments checkout session for the selected plan.

#### Scenarios
- **Happy path:** User completes payment and is redirected back to Billi with a success message.
- **Error case:** Payment is declined; user is returned to the plan selection page with an error.

### REQ-002: Plan Selection & Benefits UI
**Priority:** P1
**Description:** The system SHALL provide a clear UI comparing the Free and Premium plans, highlighting the benefits of upgrading.

#### Acceptance Criteria
- **GIVEN** an unauthenticated or free user **WHEN** accessing the settings or premium page **THEN** they SHALL see a comparison table of features (e.g., AI limits, OCR storage).

#### Scenarios
- **Happy path:** User clearly identifies the value of Premium (e.g., "Unlimited OCR").
- **Edge case:** User is already Premium; the page shows their current plan and next renewal date instead of pricing.

### REQ-003: Entitlement & Feature Gating
**Priority:** P0
**Description:** The system MUST gate premium features based on the user's active subscription status.

#### Acceptance Criteria
- **GIVEN** a free user **WHEN** they attempt to use a premium feature (e.g., advanced RAG queries) **THEN** the system SHALL show an upgrade prompt/gate.

#### Scenarios
- **Happy path:** Premium user accesses all features without restriction.
- **Error case:** Subscription expires; user's access is automatically downgraded to Free limits on the next session.

## Technical Approach
- Dodo Payments webhook handler for server-side state synchronization.
- Clerk user metadata or a `subscriptions` table to store entitlement status.
- Shared `isPremium` helper in the frontend for UI gating.

## Test Strategy
- Integration tests for webhook signature verification and state updates.
- End-to-end tests for the checkout redirect flow (using Dodo test mode).
- Unit tests for the feature gating logic.

## Implementation Plan
1. Webhook endpoint implementation and security verification.
2. Premium plans UI and checkout redirection.
3. Feature gating across the application (Chat, OCR, Export).
