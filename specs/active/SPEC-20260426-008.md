# SPEC-20260426-008: Billi AI Conversation Memory & UX

**ID:** SPEC-20260426-008
**Name:** billi-ai-memory-ux
**Stage:** CODE
**Created:** 2026-04-26
**Updated:** 2026-04-26

## Purpose

Transition the chat experience from stateless requests to a cohesive, persistent conversation using Mastra's memory system, allowing the agent to remember context and providing a superior UX for automated actions.

## Scope

### In Scope
- Implementation of Mastra Memory (Storage) using LibSQL (Turso) in the backend.
- Persistent conversation threads (per user).
- Enhanced UI components for tool-call feedback.
- Persistent thread ID management in the frontend.

### Out of Scope
- RAG ingestion (waiting for corpus data).
- Multi-user shared threads.
- Voice transcription (EP-02).

## Requirements

### REQ-001: Persistent Conversation Threads
**Priority:** P0
**Description:** The system SHALL use Mastra Memory to persist chat history between sessions.

#### Acceptance Criteria
- **GIVEN** a user sends a message
  **WHEN** no `threadId` is provided
  **THEN** the system SHALL create a new thread and return the `threadId`.
- **GIVEN** an existing `threadId`
  **WHEN** a user sends a message with that `threadId`
  **THEN** the agent SHALL respond using the context of previous messages in that thread.
- **GIVEN** a user refreshes the page
  **WHEN** a `threadId` is stored in localStorage
  **THEN** the UI SHALL fetch and display the message history for that thread.

#### Scenarios
- **Happy path: Context Memory**
  - Setup: User starts a new chat.
  - Action: User says "Recuerda que soy RESICO". Then user says "Cuál es mi régimen?".
  - Expected: Agent responds confirming the user is under the RESICO regime.
- **Edge case: Expired/Missing Thread**
  - Setup: User provides an invalid `threadId`.
  - Action: User sends a message.
  - Expected: System SHALL gracefully handle the error by creating a new thread and informing the user if necessary.
- **Error case: Storage failure**
  - Setup: Database is down.
  - Action: User sends a message.
  - Expected: System SHALL return a 500 error with a clear message that memory service is unavailable.

### REQ-002: Real-time Transaction Feedback
**Priority:** P1
**Description:** The system SHALL provide explicit UI feedback when the agent performs an automated action like `addTransaction`.

#### Acceptance Criteria
- **GIVEN** an agent calls the `addTransaction` tool
  **WHEN** the tool execution is successful
  **THEN** the chat response SHALL include metadata about the tool call.
- **GIVEN** tool call metadata in the response
  **WHEN** rendering the message
  **THEN** the UI SHALL display a "Transaction Added" card with details (Amount, Category, Date).

#### Scenarios
- **Happy path: Successful registration**
  - Setup: User is in a chat session.
  - Action: User says "Registra 200 pesos de gasolina hoy".
  - Expected: Chat shows a card saying "¡Transacción Registrada!" with "$200.00", "Gasolina", and today's date.
- **Edge case: Partial data**
  - Setup: User says "Registra 50 pesos".
  - Action: Agent asks for category.
  - Expected: No transaction card shown until the tool is actually called.
- **Error case: Tool failure**
  - Setup: `addTransaction` fails due to validation.
  - Action: User provides invalid amount.
  - Expected: Agent informs the user that the registration failed and why.

### REQ-003: History-Based Suggestion Chips
**Priority:** P2
**Description:** The system SHALL generate dynamic suggestion chips based on the user's recent activity or current financial state.

#### Acceptance Criteria
- **GIVEN** a new chat session
  **WHEN** the chat loads
  **THEN** the system SHALL show initial suggestion chips (e.g., "Ver mis gastos", "Resumen financiero").

#### Scenarios
- **Happy path: Initial suggestions**
  - Setup: User opens the chat.
  - Action: View the input area.
  - Expected: Suggestions like "Analiza mis gastos de este mes" are visible.

## Technical Approach

### Architecture
- **Backend:** Update `apps/api/src/mastra/index.ts` to include `storage` using `LibSQLStore`.
- **API:** Update `POST /ai/chat` in `apps/api/src/routes/ai.ts` to handle `threadId`.
- **Frontend:** Update `apps/web/src/routes/chat.tsx` to manage `threadId` in `localStorage` and handle tool call metadata.

### Key Decisions
- **Decision:** Use `LibSQLStore` for Mastra memory.
- **Rationale:** Aligns with existing Turso DB usage and provides Cloudflare Worker compatibility.
- **Decision:** Store `threadId` in `localStorage`.
- **Rationale:** Simplest way to persist session identity without complex auth-linked thread management for the MVP.

### Dependencies
- `@mastra/libsql`: Required for Mastra storage integration.

### Risks
- **Risk:** Mastra memory might increase latency on Cloudflare Workers.
- **Mitigation:** Ensure Turso region is close to the worker and monitor performance.
