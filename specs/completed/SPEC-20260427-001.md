## Purpose

Establish the foundational infrastructure for Retrieval-Augmented Generation (RAG) and an extensible ingestion pipeline for a comprehensive corpus of Mexican financial context. This ensures the assistant has access to a rich, high-value database of localized information that can be continuously expanded.

## Scope

### In Scope
- Database schema for RAG topics and chunks in LibSQL/Turso.
- Recursive character-based chunking strategy.
- Embedding generation pipeline using OpenAI `text-embedding-3-small` via OpenRouter.
- Idempotent ingestion script designed for large-scale, multi-source corpus management.
- Retrieval repository with vector similarity search.
- Infrastructure support for an open-ended number of financial themes and regulatory sources.

### Out of Scope
- Actual gathering and curation of the source documents (deferred).
- Frontend chat UI (covered in SPEC-002).
- Real-time indexing of user-generated content.

## Requirements

### REQ-001: Vector-Enabled Database Schema
**Priority:** P0
**Description:** The system SHALL implement a schema in Turso/LibSQL to store RAG topics and their corresponding vector embeddings.

#### Acceptance Criteria
- **GIVEN** a new piece of content **WHEN** it is ingested **THEN** it MUST be stored in the `rag_chunks` table with a corresponding vector blob of 1536 dimensions.

#### Scenarios
- **Happy path:** Successfully migrate database with vector support.
- **Error case:** Incompatible vector dimensions provided during ingestion.

### REQ-002: Scalable Ingestion & Embedding Pipeline
**Priority:** P0
**Description:** The system SHALL provide a pipeline that splits diverse document sources into manageable chunks and generates embeddings via OpenRouter using OpenAI `text-embedding-3-small`.

#### Acceptance Criteria
- **GIVEN** a directory of markdown or text documents **WHEN** the ingestion script runs **THEN** it SHALL recursively process all files, chunk them with a 50-token overlap, and generate embeddings.

#### Scenarios
- **Happy path:** Ingest a batch of documents and verify chunks/vectors in DB.
- **Performance case:** Pipeline handles a "rich" corpus (100+ documents) without timing out or exceeding rate limits.

### REQ-003: Similarity Retrieval Repository
**Priority:** P1
**Description:** The system SHALL provide a repository method to retrieve the top-K most relevant chunks based on a natural language query.

#### Acceptance Criteria
- **GIVEN** a user query **WHEN** `retrieveTopK` is called **THEN** it SHALL return the K most similar chunks using cosine similarity.

#### Scenarios
- **Happy path:** Query for "SAT basics" returns the most relevant chunks from across all ingested sources.

## Technical Approach
- Use Drizzle ORM for schema management with LibSQL vector extensions.
- Implement `bun scripts/rag/ingest.ts` for ingestion.
- OpenRouter integration for both embeddings (`openai/text-embedding-3-small`) and models.

## Test Strategy
- Unit tests for the recursive splitter.
- Integration tests for `retrieveTopK` using a local LibSQL instance.
- Mocks for OpenRouter embedding API.

## Implementation Plan
1. Schema migration and vector index creation.
2. Embedding client implementation with OpenRouter.
3. Ingestion script and repository methods.
