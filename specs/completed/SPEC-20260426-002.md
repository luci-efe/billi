# SPEC-20260426-002: Registro por Formulario Manual

**ID:** SPEC-20260426-002
**Name:** manual-transaction-form
**Stage:** QA
**Created:** 2026-04-26
**Updated:** 2026-04-26
**Author:** Gemini CLI

## Purpose

Proporcionar una interfaz estructurada y confiable para que el usuario registre transacciones financieras (ingresos/egresos) de forma manual, garantizando la integridad de los datos financieros.

## Scope

### In Scope
- Formulario de captura en `apps/web`.
- Validación de campos: monto, fecha, categoría, tipo (ingreso/egreso) y descripción.
- Endpoint `POST /api/transactions`.
- Persistencia en la tabla `transactions`.

### Out of Scope
- Captura por voz o texto libre (EP-02 posterior).
- Carga de archivos adjuntos (recibos).
- Conciliación bancaria.

## Requirements

### REQ-001: Captura Estructurada de Transacciones
**Priority:** P0
**Description:** El sistema SHALL permitir al usuario ingresar monto, fecha, categoría y tipo de movimiento mediante un formulario.

#### Acceptance Criteria
- **GIVEN** datos válidos en el formulario **WHEN** el usuario hace clic en "Guardar" **THEN** la transacción se crea en la base de datos vinculada al usuario actual.

#### Scenarios
- **Happy path:** Registro exitoso de un gasto de $150.00 en "Gasolina".
- **Error case:** Intento de guardar con monto cero o negativo.

## Technical Approach
- Usar `react-hook-form` con `Zod`.
- Reutilizar el componente `TransactionCard` o similar para feedback.

## Test Strategy
- Validación de esquema Zod en backend y frontend.
- Mock de base de datos para pruebas de repositorio.

## Implementation Plan
1. Refinar esquema de `transactions` si es necesario.
2. Implementar `POST /api/transactions`.
3. Crear pantalla de "Nuevo Movimiento" en el frontend.
