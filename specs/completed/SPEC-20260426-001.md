# SPEC-20260426-001: Configuración de Perfil y Categorías

**ID:** SPEC-20260426-001
**Name:** user-profile
**Stage:** QA
**Created:** 2026-04-26
**Updated:** 2026-04-26

**Author:** Gemini CLI

## Purpose

Permitir que el usuario configure su perfil personal, moneda predeterminada y categorías de gastos/ingresos para que el sistema refleje su realidad financiera y permita una captura de datos precisa.

## Scope

### In Scope
- Página de perfil/ajustes en el frontend (`apps/web`).
- Sincronización de datos básicos (Nombre, Email, Foto) desde Clerk.
- Persistencia de datos extendidos (RFC, Moneda) en la tabla `users` de Turso.
- Gestión de categorías personalizadas en la tabla `categories`.
- Endpoint `GET /api/me` y `PATCH /api/me`.

### Out of Scope
- Gestión de suscripciones y pagos (propio de EP-05).
- Cambio de contraseña (gestionado por Clerk fuera del app).
- Auditoría detallada de cambios en el perfil.

## Requirements

### REQ-001: Visualización de Identidad desde Clerk
**Priority:** P0
**Description:** El sistema SHALL mostrar el nombre, correo electrónico y foto de perfil del usuario obtenidos directamente de la sesión de Clerk.

#### Acceptance Criteria
- **GIVEN** un usuario autenticado **WHEN** accede a la página de perfil **THEN** ve sus datos de Clerk en modo solo lectura.

#### Scenarios
- **Happy path:** El usuario ve su nombre y foto actualizados.
- **Error case:** Error al conectar con Clerk, se muestra un estado de carga o error amigable.

### REQ-002: Persistencia de RFC y Moneda
**Priority:** P0
**Description:** El sistema SHALL permitir al usuario guardar su RFC y seleccionar una moneda predeterminada (MXN/USD) en la base de datos de Billi.

#### Acceptance Criteria
- **GIVEN** que el usuario ingresa un RFC válido y selecciona una moneda **WHEN** guarda los cambios **THEN** los datos se persisten en la tabla `users` y se reflejan tras recargar.

#### Scenarios
- **Happy path:** El usuario guarda un RFC de 13 caracteres y cambia a USD.
- **Edge case:** El usuario deja el RFC vacío (permitido si es opcional al inicio).
- **Error case:** El usuario ingresa un RFC con formato inválido.

### REQ-003: Gestión de Categorías Base
**Priority:** P1
**Description:** El sistema SHALL proporcionar un conjunto de categorías base y permitir al usuario visualizar sus categorías activas.

#### Acceptance Criteria
- **GIVEN** un nuevo usuario **WHEN** accede a la configuración de categorías **THEN** ve la lista de categorías predeterminadas del sistema.

## Technical Approach
- Extender esquema de `users` en Drizzle.
- Crear tabla `categories`.
- Implementar middleware de Clerk en Hono para proteger los endpoints.

## Test Strategy
- Pruebas unitarias para la validación de RFC.
- Pruebas de integración para los endpoints `GET/PATCH /api/me`.
- Pruebas E2E para el flujo de guardado en el frontend.

## Implementation Plan
1. Migración de base de datos (users + categories).
2. Implementación de endpoints en `apps/api`.
3. Reemplazo de stubs en `apps/web/src/routes/settings.tsx`.
